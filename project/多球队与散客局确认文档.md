## 0. 核心设计原则

1. **一套通用内核 + 可配置策略（一期只落地两支球队）**  
   抽象为 **球场（Venue）— 球队（Club）— 分组（常驻分组或当场分队池）— 本场比赛队伍**。代码按配置读策略，避免写死 `if (界龙)`。  
   **一期产品只交付「周三联 + 界龙散客」**：种子数据只写入这两支队；**不做**「新建第三支球队 / 模版市场 / 建队向导」。给其他球队的通用建队模版放二期及以后。
2. **老数据平滑兼容**  
   现有活动、报名、进球助攻、轮次归入 `club_wednesday`（周三联）。`team_jiong`、`team_pudong` 成为周三联的两个常驻分组。老用户不用重新注册。
3. **一个人可以加入多支球队**  
   顶部切换当前球队。数据可按「全部 / 某支球队 / 某常驻分组」查看。
4. **球场和球队分开，而且不绑死**  
   球场管场地，球队管人和比赛。商业化之后，一个球场接待多支球队，一支球队也可以到多个球场踢。两边用可增删的关联连接，谁也不从属于谁。某一场活动只记录这次去了哪个球场。同一个人可以既是球场主理人，又是某支球队的管理员。
5. **一个小程序，按身份切换，不拆成两个小程序**  
   使用上分成球员、球队管理、球场管理三种入口。同一个人经常兼两种身份，拆成两个小程序要注册两次、审核两次，兼职工还得来回跳。球队管理员不是球场老板，不能把球队管理放进球场端。一期只有球员和球队管理。球场管理等四期排期真正做起来再生出来。以后球场端如果变成订场、计价、员工值班这种完整后台，再考虑独立小程序，数据和账号仍共用。

## 1. 领域模型

### 1.0 球场 ≠ 球队

球场和球队是多对多。一个球场可以有多支球队来踢，一支球队也可以到多个球场踢。两边都不从属于对方。

```text
Venue 界龙足球基地
└─ 场地：1号场📹 / 2号场 / 3号场

关联（可多对多）
├─ 界龙散客 ↔ 界龙
└─ 周三联 ↔ 界龙（以后还可以再关联别的球场）

活动：先选这次去哪个已关联的球场，再选该球场的哪几块场地
```

| | 球场 Venue | 球队 Club |
| --- | --- | --- |
| 管什么 | 场地清单、以后的排期和包场 | 队员、分组、报名、赛程、比分、进球助攻 |
| 谁管 | 一名球场主理人，可加多名球场管理员 | 球队主管理员 / 球队管理员 |
| 配置 | 场地与是否运镜（一期只建数据） | 取消截止小时、候补上限、上场人数、分组池 |
| 一期 | 建 Venue 和场地；活动上勾选场地。不做球场管理页 | 完整做周三联 + 界龙散客 |

界龙散客是一支球队，只是和界龙建立了关联，不是球场的下级。周三联同样关联界龙，管理员不能改界龙的场地。新建活动时，只能选本球队已经关联的球场，再选该球场里的场地。球场老板默认同时是：界龙主理人 + 界龙散客的球队主管理员。一期不出现「球场设置」入口，关联先写在数据里：两支球队都关联界龙。

### 1.1 球队里的两种分组

| | 球队分组（两队都要维护） |
| --- | --- |
| 谁用 | 周三联、界龙散客都有 |
| 维护入口 | 主管理员在球队设置里维护本队分组名称与增减（用过的只能改名不能删） |
| 周三联预设 | `jiong 路青少年`（默认球衣**黄**）、`浦东老聚三`（默认球衣**粉白**） |
| 界龙散客预设 | 初始 **A 组～F 组**，默认色绿/白/黄/蓝/红/黑。老板可改名（如塔子🕊）、改色、调显示顺序；调顺序不改变成员归属 |
| 球衣色 | 分组上维护**默认色**；**本场队伍**上管理员仍可改本场球衣色（不回写分组默认） |
| 球员加入时 | **必选分组**。外队填坑可先标「散客」再补选 |
| 报名默认 | 进入本人分组对应本场队伍；管理员可对调/移队。周三联另有联合；**界龙无联合**。本组满可改报其他未满组。若本场未启用其常驻组：选一个本场已启用未满组报名（只写 signup，不改常驻分组） |
| 数据页「按分组」 | 周三联与界龙都要（界龙按上表六组筛） |
| 改名 | 可以（含 emoji）；已生成活动保留当时队名与当时球衣色 |

> 原「当场分队池 pool、自由点队第三模式」取消。**分队（默认进本人分组）**两边都用；**联合仅周三联**；界龙不做联合、不会后补进联队。

队内标签只用于显示，不代表任何权限。预设为「队长」「副队」「领导」「记账员」「散客」，主管理员可以改名或新增。「散客」用于外队来填坑时自动入队后的展示标记。同一个人可以有多个标签，同一个标签也可以给多个人。名册和报名名单上把标签写在名字旁边。排序仍按权限：主管理员、球队管理员、其余队员。要让某人能建活动、改名额、记分，必须另外把他设为球队管理员或主管理员。不再按昵称写死。迁移时给 `jzy`、`肉粽` 加上「队长」标签，他们原有的管理员身份保持不变。球员之后改自己的常驻分组，不回写已经报过名的场次和已有数据。

### 1.2 角色（按组织挂靠，不做权限矩阵页）

| 角色 | 挂在 | 能做 | 不能做 |
| --- | --- | --- | --- |
| 平台超管 | 全局 | 建球场/球队、授主理人和主管理员 | — |
| 球场主理人 | Venue | 一期只保存身份。四期管排期和场地配置，并可增减本球场的其他管理员 | 一期没有球场管理页。一个球场至少一个主理人，可以移交，不能减到 0 |
| 球场管理员 | Venue | 一期只保存身份。四期协助排期和场地配置 | 不能增减管理员，不能移交主理人。一个球场可以有多名 |
| 球队主管理员 | Club | 普通管理员的全部能力，外加：删活动、增减本球队管理员、改本球队配置、改队内标签 | 不能改球场排期 |
| 球队管理员 | Club | 建活动、改标题/时间/地点、改名额和分队、对调、开界龙杯、记进球事件等 | 不能删活动、不能授权、不能改球队配置 |
| 普通球员 | Club 成员 | 报名、换到空位、看数据、用战术板 | 管理操作 |

每支球队至少一个主管理员，对应现在的授权人。主管理员可以移交，不能减到 0。原周三联普通管理员迁移后仍是**周三联**的球队管理员。

**授权模型与现网相同、按球队隔离**：在「界龙散客」里由该队主管理员授权某人后，此人即可在界龙散客新建活动、一键开界龙杯、改场次、记进球事件等；**不会**因此成为周三联管理员。反之亦然。

球场主理人一期只写入 `venue_members`（与界龙散客主管理员可为同一人），不做出入口。**种子**：现网授权人同时成为周三联主管理员与界龙散客主管理员；其在各队内再授权普通管理员。

### 1.3 配置放在球队上，报名规则读配置

| 配置 | 周三联默认 | 界龙散客默认 |
| --- | --- | --- |
| `cancelSignedCutoffHours` | 4 | 4（主管理员可改成别的小时数） |
| 候补上限 | 分队每队 3；联合共享 6 | 分队后补（无联队）；另受全场正选上限约束；具体每组后补上限可配置，默认与分队类似 |
| `maxOnPitch`（战术板上场人数） | 8 | 8（同样默认 8 人制） |
| `enableTitleOdds`（夺冠概率） | 关（一期不做） | 关（一期不做；以后再开） |
| 分组模式 | 可维护分组（jiong/浦东） | 可维护分组（A～F 组） |

取消正选是否记鸽子、报名须知文案、后补默认档位，都读该球队的 `cancelSignedCutoffHours`，不写死 4。开放时段、价格、订场单放二期，一期不建这些表。

**球场** `venue_jielong` 界龙足球基地：地址、经纬度先记下。场地为 `pitch_1` 1号场（有运镜）、`pitch_2` 2号场、`pitch_3` 3号场。一期天气仍按界龙这一处取，二期再跟着活动上的球场走。

| --- | --- | --- | --- |
| `club_wednesday` 周三联 | 界龙（可再加其他球场） | jiong 路青少年、浦东老聚三 | 分队 2×11，或联合 3×8 |

## 2. 球员和管理员怎么用

### 2.1 我的、切换球队

- 「我的」里加入球队。加入周三联时选常驻分组；加入界龙散客不用选组。
- 只加入一支球队时，顶部只显示这支球队。加入多支时，首页 / 活动 / 球员顶部可切换。
- 首页大卡是**当前球队**下一场。另一支球队若也有未开始的球，大卡下用一行字提示，点进去切过去。
- 主管理员在「球队设置」改取消截止小时、候补上限、上场人数，**维护本队分组**（周三联 jiong/浦东；界龙 A～F 组），并指定管理员和队内标签。标签不带来权限。一期没有「球场设置」。
- **活动列表/卡片时间须展示周几**（如「周三 20:00」），不能只有日期数字。
- **开赛前**：主管理员与普通管理员均可改标题、开赛时间、地点；**开赛后三项均不可改**。

### 2.2 新建活动：先选预设，再微调

**报名模式（更正）**：

- **周三联**：分队 + 联合（与现网一致的名单逻辑；无比分）。
- **界龙散客**：**仅分队**，**无联合**（不会出现/后补进「联队」）。默认按球员本队分组（A～F）入队；管理员可对调/移队。
- 「默认进本人分组 + 管理员调队」两边共用；联合能力只开给周三联。

**界龙散客**可先点人数/场地预设（启用哪些组参赛），表单自动填好；老板再填 **本场正选人数上限**（全场合计，**默认 40**，管理员可改）。正选达到该上限后，后续报名只能进共享后补（即使某队还没报满，也不再扩正选，除非老板先调高上限或调分队）。默认每队按 **8 人制** 起算（与 `maxOnPitch=8` 一致），可再微调每队人数或场地。

**对战场次（已定）**：不用点界龙杯。老板把本场分成 **4、5 或 6 队**时，系统自动生成场次图（轮次、对阵、场地；6 队含轮空）。生成后可改对战双方与场地编号。2 队或 3 队不生成场次。记球口径见 §2.4。

| 预设 | 启用分组（按维护顺序前 N 个） | 场地 | 赛程 |
| --- | --- | --- | --- |
| 两队对踢 | 塔子、界龙 | 1 号场 | 未开杯无比分场次 |
| 三队轮换 | +伤心 | 1 号场 | 开杯前可手加对阵；通常 3 队不开杯 |
| 四队双场 | +汤姆 | 1 号 + 2 号 | 开杯后 3 轮循环 + 冠亚季 |
| 五队双场 | +爱情 | 1 号 + 2 号 | 开杯后 5 轮 |
| 六队双场 | +其他 | 1 号 + 2 号 | 开杯后每队 5 场；见 §2.4 |

启用顺序默认：塔子🕊 → 界龙⭐️ → 伤心🇮🇹 → 汤姆🐻 → 爱情🔥 → 散客⚽️。超过 6 组由管理员先在设置里加组再开活动。

4/5/6 队预设至少保留两块场地。减到一块场时，改用「两队对踢」或「三队轮换」，不在一块场上排双场赛程。

**开赛前调整分队**（例如 3 队×9 人改为 4 队×8 人）：

- 新的总名额必须 ≥ 已报名正选人数。
- 还没有比分时，可以改队伍数量。某一队人数超出新上限的，按报名时间从晚到早列出，确认后才挪到还有空位的队。赛程按新的队伍数重排。
- 已经记下任何一场比分之后，队伍数量锁定。每队上限可以调大，不能调到低于该队当前人数。
- 某一场已经有比分或进球后，这场的两队名单不再换人、不对调。还没有比分的队伍仍可拖拽：拖到人身上是对调，拖到空白处是移入未满的队。

### 2.3 报名

| | 周三联 | 界龙散客 |
| --- | --- | --- |
| 怎么报上 | 分队或联合；默认进本人分组；满员规则同现网。管理员可对调/移队 | **仅分队**。默认进本人组；本组满可改报其他未满组；管理员可对调/移队。正选达全场上限后后补。 |
| 后补顶上 | 与现在相同 | 有人退出，后补第 1 位进入**空出来的那一队**（且仍受本场正选人数上限约束）。之后若别的队有空位，仍可自己换过去 |
| 自己换队 | 长按自己，拖到有空位的队。满员不能挤占 | 相同 |
| 管理员对调 / 移队 | 与现在相同 | 相同 |
| 鸽子 | 距开赛小于该球队配置的截止小时，取消正选记系统鸽子。后补取消不记 | 相同，读本球队配置 |
| 外队来填坑 | 见下方「外队球员来本队活动」 | 同左 |

**外队球员来本队活动（含三期「向散客池补人」、以及其他球队成员来踢本场）**：

- 报名成功时，**自动把此人加入本场所属球队**（写入该 `Club` 的成员关系），不是「不入队的访客」。
- 名册与报名名单上 **显示为「散客」**（队内标签或成员标记即可；可与「队长」等标签并存）。
- 加入周三联时：若不选常驻分组，则以「散客」身份挂在该队，不强制塞进 jiong 路 / 浦东；之后本人可在「我的」里补选常驻分组。
- 加入界龙散客时：本来就不选常驻分组，标记「散客」即可。
- 一期仍可先只做「已是本队成员」的报名；外队自动入队 +「散客」展示在做跨队填坑时一并落地。底层不再用「未入队的 `guest`」当主路径。

### 2.4 赛程、场地、积分榜

赛制跟活动预设走，不按「场上有几支队伍」一刀切。

| 预设 | 系统做什么 |
| --- | --- |
| 周三联 · 分队 | **一期不记场次比分**；只记整场进球事件 + 出勤/鸽子。场上轮换现场安排 |
| 周三联 · 联合 | 报名分组仍可用；**一期不记场次比分与 FIFA**；球员数据同为整场进球事件 |
| 界龙 · 两队对踢 | 未开杯无比分场次；仅名单+进球事件（挂活动） |
| 界龙 · 三队轮换 | 管理员新增一轮并选择对阵双方。不要求每队场次相同。显示积分榜 |
| 界龙 · 四队双场 | 自动生成下面的前 3 轮。6 场都有比分，且没有未决的同分，才生成第 4 轮 |
| 界龙 · 五队双场 | 自动生成下面的 5 轮 |
| 界龙 · 六队双场 | 单循环 15 场，每队踢 5 场。前 7 轮每轮 2 场、2 队轮空；第 8 轮只剩 1 场，另外 4 队本轮不踢。1 号场 8 场、2 号场 7 场时，每队在 1 号场是 2 场或 3 场。具体对阵表在实现时写进测试固定下来 |
| 界龙 · 7 队及以上 | 队名继续用 G、H…；不自动排表。管理员逐场选择场地和对阵，系统照样算积分榜 |

每场卡片标明场地，并标出该队已在 1 号场踢了几场。一轮里有两场时，管理员可点「互换 1 号 / 2 号场」。只有一场时（6 队第 8 轮），改为选择这场放 1 号场还是 2 号场。

比分用空值表示还没赛，不进积分榜。0:0 表示已经踢平，算 1 分。

#### 4 队（简写 A～D = 启用顺序前四组：塔子、界龙、伤心、汤姆）

前 3 轮每轮两块场地同时开球。在这个约束下，1 号场只能是「三队各 2 场、一队 0 场」，做不到四队都至少 1 场。采用前者，避免某一队在循环赛踢满 3 场 1 号场：

| 轮次 | 1 号场 | 2 号场 |
| --- | --- | --- |
| 1 | A vs B | C vs D |
| 2 | A vs C | B vs D |
| 3 | B vs C | A vs D |

循环赛 1 号场场次：A 2、B 2、C 2、D 0。这个模板里排在第 4 位的队一场 1 号场都没有。页面标出「1 号场 0 场」，老板用互换场地调整。

第 4 轮默认：冠军赛在 1 号场，季军赛在 2 号场，并可互换。因此循环赛已踢 2 场 1 号场的队，如果再打 1 号场决赛，全赛事会是 3 场。这是「决赛优先上运镜场」的结果，由互换按钮现场调整。

#### 5 队（简写 A～E = 前五组，含爱情）

每队踢 4 场：1 号场 2 场、2 号场 2 场、轮空 1 轮。

| 轮次 | 1 号场 | 2 号场 | 轮空 |
| --- | --- | --- | --- |
| 1 | A vs B | C vs D | E |
| 2 | C vs E | A vs D | B |
| 3 | D vs E | B vs C | A |
| 4 | B vs D | A vs E | C |
| 5 | A vs C | B vs E | D |

#### 界龙散客积分榜（三队轮换、四队、五队、六队、七队及以上）

已录入比分的场次按这个顺序排名。周三联联合场不使用这张榜：

1. 积分：胜 3、平 1、负 0
2. 净胜球
3. 总进球
4. 仍相同：标「需猜拳」。管理员在这一组同分球队里拖拽排出顺序。顺序未排完之前，不生成冠亚军对阵和季军赛对阵

#### 比分、场次图与进球事件（已拍板；废弃旧「按人改整场进球/助攻总数」）

**界龙杯与场次图（仅界龙散客）**

- 默认不开启：不生成场次、不记场次比分与 FIFA 榜。
- 老板点击「开启界龙杯」：仅当队伍数为 **4 / 5 / 6** 时生成场次图（对阵、轮次、场地；6 队按预设含轮空）。支持事后改对战双方与场地编号。
- **关杯**：尚无任何场次比分、且无任何进球事件时，可关闭并清除场次图；一旦有比分或进球事件则锁死不可关。若关杯时仍发现挂 `roundId` 的事件，防御性删除或改挂到活动。
- 空值比分=未赛；0:0=踢平算 1 分（有积分榜时）。

**周三联**

- **去掉场次 / 节次比分记录**（不再记两队各节比分的产品能力，细则若需保留只读旧数据见兼容）。
- 只保留：挂在**整场活动**上的进球事件、出勤、鸽子。

**统一进球事件**

- 每条事件：必选 **进球者**；**助攻者可空**；列表一眼看出谁助攻了这个球。
- **乌龙**：`isOwnGoal` 事件（进球者=乌龙者，无助攻）；**不自动改场次比分**。
- **挂载**：
  - 周三联、以及界龙未开杯：进球/助攻/乌龙挂整场活动。
  - 界龙已开杯：进球/助攻/乌龙挂对应场次；该场次另录最终比分。积分榜按胜 3 平 1 负 0、净胜球、总进球、猜拳排出冠军。
  - 出勤和鸽子始终挂整场活动。
  - 我的组进不去时，直接进推荐组或后补，不弹确认；后补按组顶上。
- 个人进球/助攻榜 = 事件汇总（乌龙是否进进球榜待可再定，默认乌龙不进「进球榜」、可单列或计入乌龙次数）。
- **不再**提供旧的整场「给某人改进球/助攻总数」入口；旧 `contributions` 进球助攻只读兼容。
- 鸽子仍挂整场。系统自动鸽子不能改。
- 界龙开杯后：场次**最终比分**与进球事件**互不强制对齐**（可对不上）。
- 周三联：**彻底不提供比分录入**；旧节次比分**前端不展示**，库内保留不删。

### 2.5 数据页

1. 时间：近 3 个月 / 近半年 / 近 1 年
2. 球队：全部 / 周三联 / 界龙散客。选「全部」时同一个人只占一行，数字是各球队合计
3. 分组：周三联 jiong/浦东；界龙为塔子/界龙/伤心/汤姆/爱情/其他
4. 榜单仍是进球、助攻、出勤、鸽子，各前 10，并带上本人那一行

出勤、鸽子的计算口径与现在相同，只是多了球队和常驻分组两个过滤条件。


### 2.6 夺冠概率（以后再做；一期不做）

已拍板：**非一期核心**。下列设计保留作以后实现说明，一期不开发、界面不露出。能力做成可开关配置即可。

#### 球员能力分

- 管理员（球队管理员 / 主管理员）给本球队成员设定能力分，只能是 **`8` / `9` / `10`** 三档。
- 能力分挂在该球员在本球队的成员关系上（`memberships[].ability`），换球队不共用。
- 未设定时按 **`8`** 参与计算。
- 入口：球员页编辑；活动名单上也可快捷改（改的是该球员在本球队的能力分，不是只改本场）。

#### 本场队伍实力与夺冠概率

- **队伍实力** = 该队当前**正选**球员能力分之和（后补不计入；未报满也按已有正选加总）。
- **系统预测夺冠概率**：

```text
P(队 i) = 实力_i / Σ各队实力
```

  展示为百分比，保留 1 位小数，最后一队用「100% − 其余之和」兜底，保证合计 100%。
- **适用场次**：开启本能力的球队里，本场队伍数 ≥ 2 即展示。两队对踢时语义为「谁更可能赢下今晚」；三队及以上为「夺冠 / 积分榜头名」趣味预测，不替代真实赛程。
- 名单变动（报名、换队、改能力分）后：若本场概率仍是「系统值」，自动重算；若管理员已手工改过，则**不覆盖**，页面提供 **「按能力重算」**。

#### 管理员改概率

- 管理员可直接改每队百分比；改完后标记为手工值。
- 保存时校验：各队 ≥ 0，合计必须为 100%（可做「自动抹平到 100%」辅助）。
- 普通球员只读，看得见能力分档与夺冠概率，不能改。

#### 和积分榜的关系

- 夺冠概率是开赛前 / 赛中的**趣味预测**，不写入积分榜规则，也不随已踢完的比分自动贝叶斯更新（一期不做滚动态势模型）。
- 真要「按当前积分再估冠军」以后再说。**一期整节不开发。**

## 4. 实施顺序

### 一期：只交付周三联 + 界龙散客

1. 两队底座：种子只建周三联、界龙散客与界龙球场；成员、常驻分组、切球队、数据页筛选。队内标签只展示、不授权。旧数据归入周三联。**无「新建球队」入口。**
2. 散客建活动：正选上限默认 40 可改；自由选队/后补。默认不开界龙杯。
3. 老板一键开界龙杯（校验 4/5/6 队）→ 生成可改的场次图；FIFA/决赛规则仍按预设。
4. **统一进球事件引擎**：进球者+可空助攻；乌龙不改比分。周三联无场次、事件挂活动。界龙开杯后场次比分+事件挂场次；未开杯事件挂活动。废弃旧整场改总数。补测试与文档。**一期不做夺冠概率。**

一期维持：战术板、后补/鸽子规则、拖拽换队与管理员对调（在新模型上继续可用）。

一期不做：夺冠概率、球场排期页、球场设置 UI、第三支球队建队/模版、向散客池招人。主理人和球场管理员只写入 `venue_members`。活动写上 `endTime`、`sessionType`、`venueId`、`pitchIds`，供以后日历直接查。

### 二期：通用建队模版

第三支及以后球队——选 standing/pool、挂报名与赛程预设、关联球场；此时才做「开箱复制」产品能力。球场排期仍不做。

### 三期：向散客池补人 + 更多球场

周三联等差人时向界龙散客发布空位；来填坑的人自动加入目标球队并显示「散客」。再接入更多球场。

### 四期：球场排期（可再往后）

界龙 1/2/3 号场日历、包场和散客占场；主理人/球场管理员管理页；撞场检查。一期写入的 `venue_members` / 活动场地字段到这时才真正用上管理页。

## 5. 已定结论

1. 球队名：周三联、界龙散客。分组可改名、可新增；用过的不能删。
2. 界龙散客默认也是 **8 人制**（`maxOnPitch=8`）。默认本场分队名为 **A～F**；再多按 G、H… 自动顺延，不必事先起名。
3. 界龙散客本场正选人数上限为**全场合计**，**默认 40**，管理员可改；达到上限后只能后补。
4. 外队球员来本队活动填坑：自动加入该球队，名单显示「散客」；不以未入队 `guest` 为主路径。
5. 4 队前 3 轮采用「三队各 2 场 1 号场、一队 0 场」。第 4 轮默认冠军赛在 1 号场、季军赛在 2 号场，每轮可互换。
6. 6 队每队踢满 5 场。前 7 轮双场、2 队轮空，第 8 轮只踢剩下的 1 场。
7. 取消截止小时是球队配置，默认 4，各队可以不同。
8. 主管理员才能删活动、授权和改配置。普通管理员只能运营当场活动。
9. **统一进球事件**（进球者+可空助攻；乌龙不改比分）。周三联不记场次/比分，事件挂活动。界龙未开杯同；开杯后场次比分+事件挂场次。废弃旧整场改总数。界龙杯默认关，一键开且仅 4/5/6 队。
10. 「按分组统计」只统计周三联常驻分组。队长、副队、领导、记账员、散客只是标签，可多人、可叠加，不决定权限。
11. 一期球场只作为活动上的场地选项，没有球场管理功能。球场和球队是可增删的多对多。一个球场可有一名主理人和多名球场管理员。活动记下球场、场地、结束时间、`sessionType` 与（散客局）`maxSignedPlayers`。
12. 周三联联合报名不走三队积分榜。赛制由预设决定。
13. 未录入的比分是空值。记过比分的场次锁定该场名单。有分场进球时不能直接标鸽子。
14. 保持一个小程序。球员、球队管理、球场管理按身份切换。一期不做独立的球场端。
15. **夺冠概率一期不做**（以后再做；设计预留可开关）。
17. **界龙杯**：默认关；老板一键开启；开启时校验 4/5/6 队并生成可改场次图。场次比分与进球事件互不强制对齐。
18. **周三联彻底不记比分/场次**；只留进球事件、出勤、鸽子。
19. **管理员按球队授权**（同现网）：在界龙散客内授权的管理员只拥有界龙散客侧新建活动、开杯、记球等能力。现网授权人种子为两队主管理员。
20. **活动展示周几**；开赛前主管理员与普通管理员均可改标题/时间/地点；开赛后三项都锁死。
21. 旧周三联节次比分前端不展示，库保留。
22. 两队均有分组维护与默认球衣色（jiong 黄、浦东粉白；界龙六组见上表）；本场可改色；名称可改（emoji 可改）。加入必选分组。默认进本人分组；满可改报他组；本场未启用其常驻组时选已启用组报名（不改常驻）。**周三联：分队+联合；界龙：仅分队。** 数据页按分组筛。名单 UI：色点总览+一次只看一组（见精简稿 §3，待最终点头）。
23. 界龙杯：无比分且无进球事件时可关杯清场次；有比分或事件后锁死。
24. 一期维持战术板、后补/鸽子、拖拽换队。
16. **分期**：一期周三联+界龙散客；二期通用建队模版；三期补人与更多球场；四期球场排期；夺冠概率以后再做。
